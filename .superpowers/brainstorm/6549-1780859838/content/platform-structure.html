ChainGuard Platform Structure

Which page structure makes this feel like a real security platform, not a chatbot?

A

SOC Command Center (Recommended)

5 pages: Dashboard → Investigations (list) → Investigation Workspace (live) → Threat Intel → Settings

Dashboard has metrics/alerts feed. Investigations page shows all past+active. Workspace is the full investigation experience (graph, timeline, evidence, remediation). Threat Intel shows IOC database + MITRE coverage. Settings for LLM/Splunk config.

Pros

  • Judges see depth immediately
  • Each page has clear purpose
  • Feels like enterprise software

Cons

  • More pages to build (but mostly layout/display)
  • ~3 sessions of work
B

Mission Control + Workspace

3 pages: Command Center (dashboard + alerts) → Investigation Workspace (tabbed) → Admin

Fewer pages but each is richer. Command Center combines dashboard metrics with alert feed and investigation list. Workspace has tabs for Graph/Evidence/Timeline/MITRE. Admin has config + threat intel management.

Pros

  • Faster to build (~2 sessions)
  • Less navigation overhead
  • Dense, power-user feel

Cons

  • Fewer pages may seem less "thorough"
  • Tabs within tabs gets complex
C

Full Enterprise Suite

7+ pages: Dashboard → Alerts → Investigations → Workspace → Threat Intel → MITRE Matrix → Reports → Settings

Maximum page count. Every feature gets its own page. MITRE ATT&CK matrix is its own interactive view. Reports page generates investigation summaries. Separate alerts management.

Pros

  • Maximum "thoroughness" impression
  • Each page is focused and clean

Cons

  • Risk of shallow pages that feel like filler
  • 4+ sessions of work, tight for deadline
  • Some pages may feel empty without real data
